# Q22 — does USB_SEL gate the CH9102 console?

**Answered on the bench (2026-10-17), board: WAVESHARE ESP32-S3-Touch-LCD-7.**

No. `USB_SEL` (CH422G IO5) only steers **GPIO 19/20** through the FSUSB42UMX:

- IO5 **LOW** → GPIO 19/20 go to the USB-C connector (USB-Serial-JTAG / native USB).
- IO5 **HIGH** → GPIO 19/20 go to the TJA1051 CAN transceiver.

The CH9102 is on **UART0, GPIO 43/44**, a separate path. With IO5 HIGH and
TWAI running, the CH9102 console keeps working: boot logs, `picocom`, and
`esptool` uploads all succeeded while CAN was active.

Consequences:

- "CAN on" does not remove the serial console; it only takes the native USB pair.
- The recovery gap feared in the whitepaper does not exist for the CH9102 path.
  Flashing still works over the mechanical UART switch.
- The CAN-mode restart is still needed for the ESP32 ROM USB-JTAG path, but that
  path is not used by this project (`ARDUINO_USB_MODE=0`).

Verified with `/sd/status` reporting `mux_can=true` (IO5 HIGH) while a USB upload
over `/dev/cu.usbmodem5C941561291` completed successfully.
