# 26_CYD_CAN_monitor

## Overview

Two 2.8" Cheap Yellow Display (CYD) ESP32 boards connected via CAN bus,
exchanging time data and displaying received CAN messages with an LVGL-based
UI generated by EEZ Studio.

## Hardware

| Component | Specification |
|-----------|--------------|
| Board | 2.8" CYD (ESP32, ILI9341 TFT, XPT2046 touchscreen) |
| CAN Transceiver | SN65HVD230 (HS-speed) or SN65HVD232 |
| Termination | 120 Ohm resistors on both ends |
| CAN RX | GPIO 27 |
| CAN TX | GPIO 22 |
| Baud Rate | 125 kbps (standard CAN, CAN-FD not yet verified) |

### Wiring

```
CYD Board 1              CAN Bus              CYD Board 2
===============           =======              ===============
GPIO 22 (TX)  --------->| H   SN65HVDxxxx   H|<------- GPIO 27 (RX)
GPIO 27 (RX)  <--------| H   Transceiver   H|-------> GPIO 22 (TX)
GND             --------| L               L|-------> GND

120 Ohm              120 Ohm
termination          termination
(resistor)           (resistor)
```

Both boards need 120 Ohm termination resistors between CAN-H and CAN-L.
The SN65HVDxxxx transceivers typically have integrated termination, but
if not, add 120 Ohm resistors at both ends of the bus.

## Software Architecture

### Two-Board Protocol

Each board derives its CAN node ID from its WiFi IP last octet:

```
Board 1: IP 192.168.1.26  ->  CAN ID 0x1A (26)
Board 2: IP 192.168.1.27  ->  CAN ID 0x1B (27)
```

Each board broadcasts a time message every second with its own CAN ID:

```
CAN Frame:
  Identifier: 0x1A (or 0x1B for the other board)
  Data[7]:
    [0] Message type (0x01 = time message)
    [1] Seconds (0-59)
    [2] Minutes (0-59)
    [3] Hours (0-23)
    [4] Weekday (0=Sunday, 6=Saturday)
    [5-7] Reserved (zero)
```

Each board displays time messages received from the *other* board,
showing the sender's CAN ID and parsed time.

### CAN Message Display

The LVGL display shows:

1. **Title bar**: "CAN Monitor" with node ID
2. **Status line**: WiFi IP, node ID
3. **Stats line**: RX count, TX count, error count
4. **Message list**: Scrollable list of recent CAN messages

Messages are displayed as:
```
0x01A  [01 00 14 10 04 00 00 00]  16:20:00 (day 4)
```

- **Bold/larger font**: Messages whose data has changed since last seen
- **Normal font**: Messages with unchanged data
- "(local)" suffix: Messages sent by this board itself

### CAN Message Ring Buffer

A ring buffer (configurable, default 50 entries) stores received CAN
messages. When full, the oldest entries are discarded. The display
shows the most recent messages, with change detection marking those
whose data payload differs from the previous entry.

## Building and Flashing

### Build (OTA)
```bash
cd 26_CYD_CAN_monitor && pio run -e esp32ota
```

### Build (USB)
```bash
cd 26_CYD_CAN_monitor && pio run -e esp32usb
```

### Flash (OTA)
```bash
cd 26_CYD_CAN_monitor && pio run -e esp32ota --target upload
```

### Flash (USB)
Update `upload_port` in `platformio.ini` for your device, then:
```bash
cd 26_CYD_CAN_monitor && pio run -e esp32usb --target upload
```

### Monitor Serial Output
```bash
cd 26_CYD_CAN_monitor && pio device monitor
```

## EEZ Studio Integration

To design or modify the UI:

1. **Install EEZ Studio**: Download from https://github.com/eez-open/studio
2. **Open the project**: File → Open → select `26_can_monitor.eez-project`
3. **Design the UI**: Drag and drop LVGL widgets on the 320x240 canvas
4. **Export code**: Build → Export → select destination `src/ui/`
5. **Rebuild**: `pio run -e esp32ota`

The exported files (`screens.c`, `screens.h`, `ui.c`, `ui.h`, etc.)
replace the skeleton files in `src/ui/`.

### Key UI Elements

| EEZ Identifier | Purpose |
|---------------|---------|
| `lblTitle` | Title label showing "CAN Monitor" |
| `lblIP` | WiFi IP and node ID info |
| `lblStats` | RX/TX/Error statistics |
| `contMessages` | Scrollable message container |
| `lblHeader` | Column header "ID DATA" |

### Dynamic Content

The UI labels `lblIP` and `lblStats` are updated from `main.cpp`
every 500ms with current WiFi and CAN statistics. The message
container `contMessages` is rebuilt dynamically from the CAN ring
buffer, with bold font for messages whose data has changed.

## CAN Protocol Details

### Time Message Format

```c
typedef struct __attribute__((packed)) {
    uint8_t msg_type;   // 0x01 = time message
    uint8_t seconds;    // 0-59
    uint8_t minutes;    // 0-59
    uint8_t hours;      // 0-23
    uint8_t weekday;    // 0=Sunday through 6=Saturday
    uint8_t reserved[3]; // Zero padding
} can_time_message_t;
// Total: 7 bytes
```

### Standard CAN Frame (11-bit ID)

```
Frame Type:    Standard (11-bit)
Identifier:    0x001 - 0x7E0 (node-specific)
Data Length:   8 bytes (CAN FD not yet enabled)
Data:          [type][sec][min][hour][day][0][0][0]
Bit Rate:      125 kbps
```

### Extended CAN Frame (29-bit ID) - Future

CAN-FD support can be enabled by defining `CAN_FD_SUPPORTED` in
`platformio.ini`. This would allow:
- 29-bit identifiers
- Data lengths up to 64 bytes
- Higher bit rates (up to 5 Mbps)

To enable:
```ini
build_flags =
    -D CAN_FD_SUPPORTED
    -D CAN_BAUD_RATE=TWAI_TIMING_CONFIG_500KBITS()
    # Baud rate switch for CAN-FD (500k arbitration, 2M data)
```

## Troubleshooting

### No CAN messages received

1. Check wiring: TX→RX, RX→TX, GND common
2. Verify 120 Ohm termination on both boards
3. Check serial output for "[CAN] TWAI driver started"
4. Verify GPIO 22/27 are not used by other peripherals

### Display shows nothing

1. Verify WiFi connection (check serial output)
2. Check that `ui_init()` completes without errors
3. Ensure TFT_eSPI `user_setup.h` matches your CYD variant

### CAN-FD not working

1. Ensure transceivers support CAN-FD (SN65HVD232 does, 230 may not)
2. Both boards must have CAN-FD enabled with matching timing config
3. ESP32 TWAI FD driver has limited Arduino framework support
